## ERR-002: syncDailyReport logs missing detailed taskName and subtaskName information
- **Task:** T-003-001-01 · **Session:** session_003
- **File:** cloud-functions/laborSync.ts · **Line:** 138-154, 214-221
- **Symptom:** The timesheet document generated by syncDailyReport contains only the `taskId` as `taskName` inside the `workLogs` entry, and lacks any details about subtaskName.
- **Root Cause:** 1) `taskSnap.data()?.name` returned undefined because the field in the task document is actually named `taskName`, causing it to fallback to `taskId`. 2) The daily report path contains a `subtasks` index with `subtaskId`, but the code did not parse `subtaskId` from `reportPath` nor fetch the subtask's document details (like `subtaskName`). 3) The `workLogs` structure was hardcoded as `{ taskName, location }` using the incorrect `taskName` fallback and had no fields for `subtaskId` and `subtaskName`.
- **Resolution:** Modified `cloud-functions/laborSync.ts` to: 1) Retrieve task name using `taskSnap.data()?.taskName || taskSnap.data()?.name || taskId`. 2) Programmatically parse `subtaskId` from `reportPath` segments and query the subtask document to retrieve `subtaskName`. 3) Update the `workLogs` FieldValue union to write `taskId`, `taskName`, `location`, and optionally `subtaskId` & `subtaskName` if present.

## ERR-003: syncDailyReport misses editHistory syncing from daily report to DailyEmployeeTimesheets
- **Task:** T-003-002-01 · **Session:** session_004
- **File:** cloud-functions/laborSync.ts · **Line:** 239, 339, 360
- **Symptom:** When a foreman edits a Daily Report on Aftersale's side and the sync is triggered, the edit history (editHistory array field containing snapshot logs and reasoning) is not saved or updated inside the corresponding documents in the DailyEmployeeTimesheets collection.
- **Root Cause:** The `syncDailyReport` HTTPS Cloud Function constructed and merged timesheet documents for both active labor records (`laborEntries`) and leaves (`leaveEntries`) by mapping only standard fields (expectedShifts, expectedHours, shiftTimes, workLogs, leaveStatus, lastUpdated, sourceReport, AssigneesID, photos), completely omitting the `editHistory` field from `reportData`.
- **Resolution:** Modified `cloud-functions/laborSync.ts` to retrieve `reportData.editHistory` and include `editHistory: reportData.editHistory || []` in all timesheet construction blocks (for labor, part-day leaves, and full-day leaves) before committing via `batch.set(..., { merge: true })`. Verified TypeScript compilation successful.
